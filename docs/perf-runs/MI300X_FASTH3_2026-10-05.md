# MI300X (gfx942) — FastH3 dense 4-step LoRA, 832×480 · 5 s

2026-10-05. DORobot, AMD Instinct MI300X VF (`gfx942`), VRAM total
**191.69 GiB**. Branch `mi300x-fasth3`, `make HIP_ARCH=gfx942 -j20 h3`.
Model `/mnt/doscratch/MiniMax-H3`. Adapter
`FastVideo/FastVideo-FastH3-4-step-Preview-v1-LoRA`,
`dense-datafree/adapter_model.safetensors`, strength 1.0. Seed **42**.

`--fasth3-lora` is off unless the path is set. The base stays official
MiniMax-H3. Load merges all **809** adapter tensors into the existing
weights, then the usual INT8 quantize runs. The schedule is the distilled
ladder **999, 749, 500, 250** (four DiT evaluations, shifts 12 and 3),
which replaces `--steps`. Layers stay **50**, `--reuse 1`. Token
reduction, `--sol-attn`, `--fbc`, SSD streaming, and core reuse above 1
are rejected. The VSA adapter is a different file and was not loaded.

This is the same canvas as
[`MI300X_ONDEVICE_2026-10-05.md`](MI300X_ONDEVICE_2026-10-05.md):
**832×480**, 24 fps, **124 frames**, **5.167 s**. The dense row below is
that ledger's INT8 process E2E. It is not the 2026-09-12 / 2026-09-18
`bench/` scoreboard.

```bash
./h3 --profile -d /mnt/doscratch/MiniMax-H3 \
  --fasth3-lora /mnt/doscratch/FastH3/dense-datafree/adapter_model.safetensors \
  -p 'Cinematic push-in on a starship bridge: a captain in a high-collared navy tunic stands silhouetted at the observation window as a dreadnought armada charges its hyperdrives. A blinding flash, the bridge shudders, and the fleet is gone.' \

  --layers 50 --reuse 1 --seed 42 \

```

`--use-slower-bf16-mlp --use-slower-bf16-qkv --use-slower-bf16-attention-output`.
Its core quantize line is **0.000 s**. The INT8 arm is the default DiT
path; core quantize is **0.041 s**.

## Same-fixture comparison

Process E2E is `/usr/bin/time` until `h3: wrote`. The BF16 run was not
wrapped in `time`. Its profiled phase walls sum to **31.021 s** (text
3.331 + DiT 17.507 + audio VAE 0.512 + video VAE 9.671).

| path | E2E | denoise | sdpa / linear | video VAE | attention | denoise peak |
|---|---:|---:|---|---:|---:|---:|
| dense, 50-step INT8 | **166.87 s** | 136.723 s | 75.998 / 49.233 s | 9.807 s | 2500 | 22.657 GiB |
| FastH3, 4-step BF16 | — | 12.040 s | 5.960 / 5.149 s | 9.671 s | 200 | 38.885 GiB |
| FastH3, 4-step INT8 | **30.12 s** (5.54×) | 10.878 s | 6.029 / 3.911 s | 9.628 s | 200 | 21.902 GiB |

INT8 phase walls: text encoder 2.354 s, DiT load 5.465 s, Euler denoise
**10.878 s**, audio VAE 0.512 s, video VAE 9.628 s. Those walls sum to
28.864 s; the 30.12 s process E2E leaves about 1.3 s for mux and startup.
Denoise other is 0.875 s. Both FastH3 logs print
`h3: FastH3 merged 809 adapter tensors`.

Denoise scales with the evaluation count. 136.723 × 4/50 = **10.94 s**,
and the INT8 denoise is **10.878 s** (**12.57×**, against 50/4 = 12.5×).
SDPA stays about 6.0 s in both BF16 and INT8. The INT8 linear drop
(5.149 → 3.911 s) is the quantize. BF16 keeps the merged weights in
BF16, so the denoise peak is **38.885 GiB** instead of **21.902 GiB**.

Video VAE does not move (9.8 s, 9.7 s, 9.6 s; tiles 4×2 at 272 px). On
the INT8 run it is **32%** of the 30.12 s process. Audio VAE stays
0.51 s. Text-encoder wall is shorter than the dense run's 8.399 s
because that dense process read the text weights at 0.57 GiB/s; the
FastH3 reads were 2.40 GiB/s (BF16) and 7.81 GiB/s (INT8). The 5.54×
process ratio therefore includes a warmer load. The denoise ratio is
the step-count comparison.
