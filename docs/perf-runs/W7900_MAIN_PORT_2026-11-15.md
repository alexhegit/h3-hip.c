# W7900 (gfx1100) on main v0.20.0 — port and follow-up work

Branch `w7900-v2`, from `origin/main` `e99d274` (v0.20.0). The earlier
`w7900` branch (PR #14) forked before the R9700 work landed on main, and
main fixed most of the same problems on its own: the device reserve on
cards below 48 GiB, INT8 row chunking, batched grouped INT8 with a
loop-order reduce, the prefetch / transposed-V / DPP wave32 SDPA (`PF`),
BF16 VAE activations, and a prompt-embedding + AdaLN disk cache. Merging
`main` into `w7900` conflicts in 12 files, mostly two implementations of
the same fix, so this branch starts from main and adds only what gfx1100
still needed. Each step is measured on the W7900.

Machine and fixture as in [`W7900_2026-11-09.md`](W7900_2026-11-09.md):
1344×768 · 15 s (362 frames, 109,334 DiT tokens), 20 steps, 45 layers,
`--reuse 2`, seed 42, weights on a 7200 rpm disk, `HIP_VISIBLE_DEVICES=0`,
`H3_FFMPEG=/usr/bin/ffmpeg`.

## gfx11 S^T/O^T SDPA

main's gfx12 kernel computes S^T = K Q^T and O^T = V^T P^T so the score
accumulator is already the P^T operand. On gfx11 the accumulator interleaves
rows (element e of lane l is key 2e + (l>>4)), so lanes l and l^16 swap four
BF16 per 16-key tile to build the operand. The row-sum tree keeps the PF
kernel's xor-1/2/4/8 pairing (level 1 across the lane pair, levels 2–4
in-lane).

It still cannot be bit-identical: on gfx1100, `A·Xᵀ` and `(X·Aᵀ)ᵀ` differ in
29 of 256 outputs of a 16×16 WMMA tile, so swapping the operand roles
changes rounding (gfx12 does not). Per call the difference is at BF16
rounding level (max |Δ| 3.8e-6 at 109k tokens), but the video becomes a
different sample, so PF stays the default.

| tile (waves × BK), L = 109334, 8 heads | PF | S^T/O^T |
|---|---:|---:|
| 8 × 32 | **53.4** | 56.9 |
| 16 × 32 | 48.4 | **61.1** |
| 16 × 16 | 49.0 | 57.3 |
| 4 × 32 | 47.6 | 54.7 |

44k tokens: 59.4 (S^T/O^T, 16 waves) vs 51.4–55.6 (PF). With the opt-in on,
16 waves is the default tile.

## End to end with the caches (`12bd4e3`, frozen binary)

`H3_DISK_CACHE_DIT_INT8=1 H3_CACHE_MAX_GIB=48`, run back to back on
2026-11-16. The cache directory ends at 34 GiB (two runs' INT8 cores: the
T11 run's `H3_SDPA_WMMA_T` changes every key).

| 1344×768 · 15 s | populate | **warm (default)** | `H3_SDPA_WMMA_T=1` (cold keys) | `--token-reduction`, warm |
|---|---:|---:|---:|---:|
| text encoder | 363 s | skipped (prompt cache) | 363 s | skipped |
| AdaLN | 176 s | 2.4 s | 175 s | 2.2 s |
| transformer core | 331 s | 43 s | 316 s | 100 s |
| denoise | 4016 s | 4013 s | **3558 s** | 2410 s |
| SDPA / linear | 3367 / 583 s | 3370 / 576 s | **2915** / 576 s | 1937 / 414 s |
| video VAE | 143 s | 143 s | 143 s | 143 s |
| process E2E | 5046 s | **4217 s** | 4571 s | **2671 s** |
| md5 | `48ab9821…` | `48ab9821…` | `63d83276…` | `aed15296…` |

- Default path, warm: **4217 s**, against 5171 s on `w7900` `bd209a7` and
  4624 s with that branch's own weight cache; same md5.
- The S^T/O^T opt-in takes denoise 4013 → 3558 s (−11%, SDPA −13.5%). With
  warm keys that is ~3760 s E2E. Its video is a different sample (20.7 dB /
  SSIM 0.80 against the default clip, like any reordering of the sums), not
  a visibly worse one.
- TR, warm: 2671 s (3571 s on `w7900`), 16.6 dB against dense.
- Transformer-core read time on a hit depends on how much of the 17 GiB is
  still in page cache (43 s right after populate, 100 s after another
  run).

## Not done / notes

- INT8 QKᵀ SDPA: gfx1100 runs `v_wmma_i32_16x16x16_iu8` at the bf16 rate
  (~101 TOPS each), so it would not speed SDPA up
  ([`W7900_2026-11-09.md`](W7900_2026-11-09.md)).
- The weight cache from `w7900` (`H3_WEIGHT_CACHE_DIR`) is not ported;
  main's disk cache covers the AdaLN tables and adds prompt embeddings, and
  `H3_DISK_CACHE_DIT_INT8` covers the INT8 core.
