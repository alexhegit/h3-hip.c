# W7900 (gfx1100) on main v0.20.0 — port and follow-up work

Branch `w7900-v2`, from `origin/main` `e99d274` (v0.20.0). The earlier
`w7900` branch (PR #14) forked before the R9700 work landed on main, and
main fixed most of the same problems on its own: the device reserve on
cards below 48 GiB, INT8 row chunking, batched grouped INT8 with a
loop-order reduce, the prefetch / transposed-V / DPP wave32 SDPA (`PF`),
BF16 VAE activations, and a prompt-embedding + AdaLN disk cache. Merging
`main` into `w7900` conflicts in 12 files, mostly two implementations of
the same fix, so this branch starts from main and adds only what gfx1100
still needed. Each step is measured on the W7900.

Machine and fixture as in [`W7900_2026-11-09.md`](W7900_2026-11-09.md):
1344×768 · 15 s (362 frames, 109,334 DiT tokens), 20 steps, 45 layers,
`--reuse 2`, seed 42, weights on a 7200 rpm disk, `HIP_VISIBLE_DEVICES=0`,
`H3_FFMPEG=/usr/bin/ffmpeg`.

## gfx11 S^T/O^T SDPA

main's gfx12 kernel computes S^T = K Q^T and O^T = V^T P^T so the score
accumulator is already the P^T operand. On gfx11 the accumulator interleaves
rows (element e of lane l is key 2e + (l>>4)), so lanes l and l^16 swap four
BF16 per 16-key tile to build the operand. The row-sum tree keeps the PF
kernel's xor-1/2/4/8 pairing (level 1 across the lane pair, levels 2–4
in-lane).

It still cannot be bit-identical: on gfx1100, `A·Xᵀ` and `(X·Aᵀ)ᵀ` differ in
29 of 256 outputs of a 16×16 WMMA tile, so swapping the operand roles
changes rounding (gfx12 does not). Per call the difference is at BF16
rounding level (max |Δ| 3.8e-6 at 109k tokens), but the video becomes a
different sample. It was opt-in at first; `bebe8eb` makes it the gfx110x
default (below).

| tile (waves × BK), L = 109334, 8 heads | PF | S^T/O^T |
|---|---:|---:|
| 8 × 32 | **53.4** | 56.9 |
| 16 × 32 | 48.4 | **61.1** |
| 16 × 16 | 49.0 | 57.3 |
| 4 × 32 | 47.6 | 54.7 |

44k tokens: 59.4 (S^T/O^T, 16 waves) vs 51.4–55.6 (PF). With the opt-in on,
16 waves is the default tile.

## S^T/O^T as the gfx110x default (`bebe8eb`)

The S^T/O^T kernel is now the default on gfx110x (`H3_SDPA_WMMA_T=0`
restores PF; gfx1151 keeps PF until it is timed there). The W7900 md5
changes with it. `h3_hip_bf16_tests` checks Sol-Attn keep-all against
dense within 1e-4 on gfx110x (3.1e-5 measured) and bitwise elsewhere or
with `H3_SDPA_WMMA_T=0`.

What is left inside that kernel, at 109k tokens × 8 heads, 16 waves × BK 32
(62.4 TFLOPS, 192 VGPRs, 8 waves per SIMD, ~2.1 GHz). The first four rows
remove work and give wrong output; they only bound what each part costs.

| variant | TFLOPS | bits vs default |
|---|---:|---|
| default | 62.4 | — |
| no `exp` (P = S, α = 1) | 65.0 | bound only |
| K fragments read once, outside the loop | 61.9 | bound only |
| K and V fragments read once, outside the loop | 65.9 | bound only |
| `-mcumode` | 59.7 | identical |
| double-buffered K/V tile, one barrier per tile | 51.6 (246 VGPRs) | identical |
| same, loop unrolled by 2 with fixed buffers | 51.2 | identical |
| xor-16 exchanges via `ds_swizzle` SWAP16 | 62.6 | identical |
| xor-16 exchanges via `v_permlanex16` | 62.9 | identical |

No single part dominates: `exp` and all K/V LDS traffic are 4–6% each,
and the 168 `ds_swizzle` per tile that rocWMMA emits to replicate gfx11
A/B operands across the half-waves are not the limit either. RDNA3 issues
WMMA on the VALU, so its 32 WMMA per tile (~1024 cycles) and ~400 VALU
instructions cannot overlap; that caps this structure near 70% of the
101 TFLOPS WMMA peak, against 62% now. Double buffering frees a barrier
but costs 54 VGPRs and drops occupancy from 8 to 6 waves. Nothing above
was kept.

## End to end with the S^T/O^T default (`bebe8eb`, frozen binary)

Same fixture and cache settings, run back to back on 2026-11-17. PSNR is
FFmpeg `psnr` of the video against the warm dense clip from this build.
The fbc, Sol-Attn and FastH3 switches set `H3_*` variables, which enter
every disk-cache key, so those three runs missed the prompt-embedding,
AdaLN and INT8-core caches and paid ~800 s of load (~550 s for FastH3,
whose LoRA core is never cached). The "warm, est." row subtracts that.

## Not done / notes

- INT8 QKᵀ SDPA: gfx1100 runs `v_wmma_i32_16x16x16_iu8` at the bf16 rate
  (~101 TOPS each), so it would not speed SDPA up
  ([`W7900_2026-11-09.md`](W7900_2026-11-09.md)).
- The weight cache from `w7900` (`H3_WEIGHT_CACHE_DIR`) is not ported;
  main's disk cache covers the AdaLN tables and adds prompt embeddings, and
  `H3_DISK_CACHE_DIT_INT8` covers the INT8 core.
